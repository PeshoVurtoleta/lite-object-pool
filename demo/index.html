lite-object-pool / v2.3.1 / zero-GC object pool

One preallocated pool, thousands of objects a second. Fire a burst, hold a firehose, or spring a leak and watch the /debug lane name the call site. The telemetry you are reading is written by stats(out) into ONE scratch object every frame -- the readout costs zero allocation.

burst / the OP-01 spike workload, live0 active

Click or drag the scope to spawn a burst. Each particle is acquire()d from a fully preallocated pool and release()d when it dies -- the spike this package exists to absorb, at 0 B/op. When the pool is empty the burst is simply smaller: no allocation, no GC pause.

Cost per acquire on the debug lane (llms.txt): ~102 B with captureStacks off, ~1173 B (~1.2 KB) with it on -- this scene runs it ON, to name the site. That is why this is a SEPARATE subpath, not the shipping hot path: scenes 1 and 2 use the plain ObjectPool at 0 B/op. watchPool is NOT used here -- _items[] retains every pooled object, so a pool escape is impossible by construction and the canary would read zero forever.
